## 읽는 순서 추천

- **새로 합류하는 개발자**: 00 → 03 → 06 → 04 → 05
- **PM / 기획**: 00 → 01
- **DevOps / SRE**: 07 → 10 → 08
- **DB / 데이터 엔지니어**: 04 → 05 → 11
- **보안 리뷰**: 08 → 04 → 07

## 갱신 원칙

1. 코드 변경 PR 에 문서 변경을 같은 커밋으로 묶어라.
2. 본 문서들은 "왜" 와 "전체 그림" 을 다룬다. "무엇" 은 코드를 보면 알 수 있다.
3. 파일 경로는 `src/path/file.ts:line` 형식으로 적어 클릭 내비게이션이 가능하게 한다.
